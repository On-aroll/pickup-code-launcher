一个把截图、短信文字中的快递通知整理成「按取件地点分组的待取清单」的 Android 工具。保留各平台快捷入口，附带的网页版仍是入口集合，不具备 Android 清单功能。

作者：EyanLiu。本仓库从 [EidenLiu/pickup-code-launcher](https://github.com/EidenLiu/pickup-code-launcher) 迁移并继续维护。

## 已实现

- 快速打开菜鸟、淘宝和拼多多取件码
- 一键跳转到淘宝订单列表、拼多多订单页
- 查看京东、小红书待取快递
- 查看抖音、快手、哔哩哔哩订单列表
- 批量导入截图（每批最多 30 张），或一次粘贴多条通知
- 内置中文文字识别，提取数字码、字母数字码、横杠货架码，例如 `083620`、`A-02-0038`、`2-103-4567`
- 识别明确的驿站/门店/快递柜名称、地址、快递公司；一条通知中的多个码拆成多件
- 导入后进入待核对；可对照识别原文修改，完整无冲突项支持批量确认
- 按完整取件点名称与地址分组，显示总件数、地点数、本站件数，复制单码、本站清单或待取总表
- 可搜索、统一修改组内地点、标记已取、恢复待取、删除本机记录
- 完全相同的活动通知重复导入会跳过；同地点同码但不同通知会提示核对，不擅自删掉可能共用码的包裹
- 对应 App 无法打开时，按入口配置尝试网页、App 首页或提示安装
- 支持应用长按快捷操作
- 支持将任意入口固定为独立桌面图标
- 支持五按钮 Android 桌面小组件
- 不读取短信、通知或账号数据，不申请全相册访问权限
- 不需要网络权限和后端服务

## 使用：把所有快递整理到一起

1. 首页选择「导入多张截图」或「粘贴通知」。保留通知中的地点和码，不必只裁出数字。不同文字通知之间空一行有助于区分。
2. 在「待核对」查看每件的码、地点、地址与识别原文；缺字段或对应关系不明确的项需要补充。无警告的完整项可点「核对完整项」预览后批量确认。
3. 「待取」按取件点归组，例如总共 6 件、3 个地点，每站列出所有货架码/柜码。可以复制本站清单，也可复制所有待取件。
4. 同一地点叫法不一致时，用「统一地点」改为相同名称和地址。取完点「已取」，误点可以从已取页恢复。

`examples/取件通知示例.txt` 提供 6 件、3 个地点的文字示例，可复制试用；应用不会自动塞入演示数据。

### 范围与隐私

截图文字识别在本机执行，中文模型随 APK 内置，无需首次下载模型。只读取主动选择的图片，不读取短信、通知或账号。码、取件点和识别原文存在本机数据库，不保存原始图片、不上传；取件数据库及导入摘要排除在系统备份与设备迁移规则之外。卸载/清除应用数据会丢失清单，可先复制需要保留的内容。

归纳是规则提取和分组，不是平台订单同步，也不保证识别任意布局。图片模糊、极长截图缩小、多列排版、缺失地点、没有明确码标签时可能漏识别或对应错误；电话号码和运单长号不会默认当取件码。无法判断的内容会保留为草稿，必须核对原通知；不支持扫码开柜、自动提交取件码或路线规划。

批量处理不依赖当前页面，旋转或切换页面不丢已保存记录；若系统杀死进程，未完成部分不会自动续传，需要重新选择图片，已完成的完全重复通知会跳过。

尚无真实手机截图集的准确率报告。`ocr-model` 的 99.75% 是旧数字实验的合成数据结果，不能用于宣称当前识别准确率。

## Android 构建

需要 JDK 17 和 Android SDK 35：

```powershell
.\gradlew.bat assembleDebug
```

调试 APK 输出到：

```text
app/build/outputs/apk/debug/app-debug.apk
```

推送 `v` 开头的 git 标签（如 `v2.1.0`）会自动触发 GitHub Actions 构建并发布 Release。

## Android 发布版签名

发布前请创建自己的签名证书，并在后续版本中一直使用同一个证书：

```powershell
keytool -genkeypair -v -keystore release-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias kuaidi_qujian
```

复制 `keystore.properties.example` 为 `keystore.properties`，填入签名信息，然后执行：

```powershell
.\gradlew.bat assembleRelease
```

签名文件和密码不能上传到公开仓库。以后更新应用必须继续使用同一个签名文件。

如果使用 GitHub Actions 发布，可以把 keystore 以 base64 编码后存为仓库 Secret，并在仓库中配置 `KEYSTORE_BASE64`、`KEYSTORE_PASSWORD`、`KEYSTORE_ALIAS`，流水线会自动进行签名。密钥密码不同时还需配置 `KEYSTORE_KEY_PASSWORD`，未配置则沿用 keystore 密码。缺少签名配置时发布失败，不会用调试签名替代，以免老用户无法覆盖升级。

发布前运行 `testDebugUnitTest lintRelease assembleRelease`，再用原签名校验 APK。还需要在真机上检查选图、识别中退出、修改复制、各平台跳转和旧版覆盖安装。

## 链接维护

应用使用第三方 App 的内部页面入口，这些入口并非稳定的开放 API。发布前应在安装了最新版对应 App 的真机上逐个测试。

## 常见问题

**点击入口后打开的是 App 首页，而不是取件页。**

第三方 App 更新后可能调整内部页面地址。请先把对应 App 升级到最新版再试；仍不行时，使用应用内置的网页入口，或到 Issues 反馈。

**首页待取件列表是空的。**

本地清单不会读取平台账号。先导入截图或文字，在「待核对」确认后才会进入「待取」。平台入口里的订单列表则需要在对应 App 登录。
